# Як ми працюємо над GGMap

## Гілки
- `main` — завжди робоча версія, прямі push заборонені (тільки через PR).
- Робочі гілки від `main`: `feat/<коротко>`, `fix/<коротко>`, `chore/<коротко>`, `docs/<коротко>`.
  Приклад: `feat/map-markers`, `fix/login-crash`.

## Коміти — Conventional Commits
```
feat: додано шар маркерів на карту
fix: виправлено падіння при порожньому списку
refactor: винесено API-клієнт в окремий модуль
docs: оновлено README
chore: оновлено залежності
```

## Цикл задачі
1. Issue з описом і критеріями готовності.
2. Гілка від свіжого `main`.
3. Невеликі коміти → push → Pull Request (шаблон заповнюється автоматично, `Closes #N`).
4. CI має бути зеленим, рев'ю → **Squash and merge**.
5. Гілка видаляється після злиття.

## Релізи
Семантичні версії `vMAJOR.MINOR.PATCH` через теги та GitHub Releases.

## Секрети
Ключі API та паролі — тільки в `.env` (не комітиться) та GitHub → Settings → Secrets.
У репозиторії лише `.env.example` з назвами змінних без значень.
